# Deterministic mechanics

The simulation runs at 60 ticks per second. A held cardinal input tries to move one grid cell every six ticks. Events are ordered by `(tick, sequence)`. A later sequence wins; equal-sequence direction downs use the canonical Up, Right, Down, Left precedence regardless of source-array order. Timed switches require an interact down edge while the actor is on the switch; merely standing on one does nothing.

Pause is outside the step loop. The UI releases every locally held action when pause begins and accepts later keyup events, so a lost browser keyup cannot leave a stuck movement. A committed echo releases all inputs after its final tape event is processed and holds its final cell until the room ends.

The default real-time mode keeps held keyboard and touch-button input. Optional step mode emits the same canonical down/up tape events, then advances the same model by exactly six ticks per direction, Interact, or Wait action. Every step advances the player, echoes, guards, timers, and budget together; no wall-clock interval advances while step mode is selected. Changing mode, pausing, or leaving the window releases held input. The saved mode defaults to real-time for older saves and invalid modes are rejected transactionally.

Doors test occupancy and timers before movement. A player already in a door cell is not ejected if a door closes. Timers are valid while `remaining > 0`; device evaluation happens before the one-tick decrement. Guard movement is deterministic: a patrol tries its next authored cell on cadence, waits when an echo occupies that target, and never searches for an alternate path. Authored guards may have a declared start tick, so a lesson can make the blocker matter at the crossing rather than at room start. Guard/player contact, including a direct swap across cells, is a collision. Terminal order is collision, hazard, exit success, then budget failure.

Player keys reset on every attempt. Echoes can activate devices and block guards but cannot collect keys, carry key state, open the exit, or complete a room. Room 5's baton is therefore the player carrying the key while the echo carries plate duty.

Authored solutions contain executable `play`, `record`, `rewind`, `erase`, and `retry` steps where the lesson needs them. The validator certifies each stored route against a stable fingerprint. Alternative routes are accepted when they replay to success; they are not forced to match the authored input tape. A trailing release after a terminal success can therefore be omitted, while a release that defines an echo's useful hold duration remains meaningful.
